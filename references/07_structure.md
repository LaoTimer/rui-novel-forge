# 四层瀑布 + Fabula/Discourse + 分卷（Structure）

> 故事的"结构"分两层：故事本身（Fabula）怎么发生 + 怎么讲给读者听（Discourse）。本引擎融合《救猫咪》、博克 PROBLEM、四层瀑布、三态情感，给出从骨架到分卷的完整方法。

## 整体结构框架

```
L1 故事内核（Core）           ← 故事线公式 [见 03_storyline.md]
  ↓
L2 架构层（Architecture）     ← 四层瀑布（种子/编排/架构/叙事/渲染）
  ↓
L3 叙事层（Narrative）        ← Fabula/Discourse 解耦
  ↓
L4 渲染层（Rendering）        ← 风格锚定 + 声音指纹
  ↓
L5 反馈层（Feedback）         ← 体检 + 评审 + 续命
```

## L2 架构层：四层瀑布创作模型

来自联网取经，融合到本引擎。

### 四层定义

| 层级 | 名称 | 内容 | 输出 |
|------|------|------|------|
| L1 | 种子层 | 核心概念、主题种子、情感内核 | 一句话故事线 |
| L1.5 | 编排层 | 创作意图解析、功能标注映射 | 意图清单 |
| L2 | 架构层 | 场景序列、冲突链、节奏曲线 | 骨架+分卷+分章 |
| L3 | 叙事层 | 视角选择、时序编排、信息控制 | 章节 spec |
| L4 | 渲染层 | 文字润色、比喻精准、风格统一 | 正文 |

### 层间流转

```
L1 → L1.5：种子意图化，提取创作目标
L1.5 → L2：意图结构化，生成场景蓝图
L2 → L3：结构叙事化，确定呈现方式
L3 → L4：叙事文本化，完成最终输出
```

### 逆向校验

```
L4 → L3：文本是否准确呈现叙事意图
L3 → L2：叙事是否支撑结构设计
L2 → L1.5：结构是否服务于创作意图
L1.5 → L1：意图是否源于核心种子
```

## L3 叙事层：Fabula/Discourse 解耦

**这是本引擎新增的核心方法论**，来自国际写作方法。

### 两个核心概念

| 概念 | 定义 | 特征 |
|------|------|------|
| **Fabula（故事本体）** | 按时间顺序发生的全部事件 | 客观存在、时序完整、因果链清晰 |
| **Discourse（叙事呈现）** | 向读者展示故事的方式 | 主观编排、时序可变、信息可控 |

### 解耦的 4 大优势

1. **创作自由度提升**：故事线独立设计，叙事线灵活调整
2. **多线叙事/倒叙/插叙** 变得可控
3. **伏笔埋设与回收** 精确控制
4. **修改效率提升**：故事逻辑改 Fabula，呈现效果改 Discourse

### 模板

**Fabula 层（故事本体）**：
```yaml
fabula:
  objective_events:    # 按时间顺序
    - time: T1
      event: 主角父亲被杀
    - time: T2
      event: 主角开始寻仇
    - time: T3
      event: 主角发现凶手是师父
  causal_chain:        # 事件因果
    - T1 → T2：因杀父而寻仇
    - T2 → T3：因追寻而发现
  character_states:    # 角色真实状态
    - 主角：复仇者 + 迷茫
    - 师父：凶手 + 愧疚
```

**Discourse 层（叙事呈现）**：
```yaml
discourse:
  narrative_order:     # 实际呈现顺序
    - 第 1 章：T3 真相揭示（开篇震撼）
    - 第 2 章：T1 倒叙（杀父背景）
    - 第 3 章：T2 寻仇过程
  pov_choice: 第一人称（主角）
  info_hiding:         # 隐藏的信息
    - 凶手是师父（开篇前 5 章不揭示）
    - 主角与师父的师徒情
  info_release:        # 按节奏释放
    - 第 1 章：开篇真相炸出
    - 第 5 章：师徒情铺垫
    - 第 10 章：真相再深化
```

### 实战用法

每个章节 spec 必须明确：
1. **本章节 Fabula**：本章"客观发生了什么"
2. **本章节 Discourse**：本章"怎么讲给读者听"
3. **本章节的功能**：在整体 Discourse 中起什么作用（铺垫/高潮/转折/过渡）

## L2 架构层：骨架设计

### 骨架的 3 元素

| 元素 | 功能 | 工具 |
|------|------|------|
| 故事线 | 故事 DNA | L1 公式（见 03） |
| 节拍 | 关键转折点 | 15 节拍（见下） |
| 卷结构 | 整体结构 | 6-8 卷规划 |

### 《救猫咪》15 节拍（核心节拍，必背）

| # | 节拍 | 功能 | 占全卷% |
|---|------|------|---------|
| 1 | 开场画面 | 主角日常世界+核心冲突暗示 | 1% |
| 2 | 主题陈述 | 副线/朋友点出主题 | 5% |
| 3 | 铺垫 | 主角日常、缺陷、渴望展示 | 1-10% |
| 4 | 催化剂 | 改变主角命运的事件 | 10% |
| 5 | 辩论 | 主角犹豫要不要接受召唤 | 10-12% |
| 6 | 决定 | 主角决定进入新世界 | 12% |
| 7 | B 故事 | 副线启动（爱情/友情/师徒） | 20-25% |
| 8 | 娱乐游戏 | 主线推进中的"承诺前提"展示 | 20-50% |
| 9 | 中点 | 主角从被动转主动 / 假胜利/假失败 | 50% |
| 10 | 反派逼近 | 外部压力增大 | 50-75% |
| 11 | 一败涂地 | 主角失去一切/顿悟 | 75% |
| 12 | 灵魂暗夜 | 主角最低谷 | 75-80% |
| 13 | 决胜时刻 | 主角用新信念行动 | 80-99% |
| 14 | 高潮 | 正面对决 | 99% |
| 15 | 收场画面 | 新日常（与开场画面形成对比） | 100% |

### 15 节拍 vs 卷章映射

**网文 1 卷 ≈ 30-50 章**：

| 节拍 | 在 1 卷中的章节位置 |
|------|------------------|
| 开场画面 | 第 1-2 章 |
| 主题陈述 | 第 2-3 章 |
| 铺垫 | 第 3-8 章 |
| 催化剂 | 第 8-10 章 |
| 辩论 | 第 10-12 章 |
| 决定 | 第 12-15 章 |
| B 故事 | 第 15-20 章 |
| 娱乐游戏 | 第 20-30 章 |
| 中点 | 第 30-35 章 |
| 反派逼近 | 第 35-50 章 |
| 一败涂地 | 第 50-55 章 |
| 灵魂暗夜 | 第 55-60 章 |
| 决胜时刻 | 第 60-65 章 |
| 高潮 | 第 65-68 章 |
| 收场画面 | 第 68-70 章 |

### 不同卷位的节拍差异

| 卷位 | 节拍特征 | 类型侧重 |
|------|---------|---------|
| 首卷 | 完整 15 节拍，开场画面+铺垫占比最高 | 主类型纯血 |
| 中间卷 | 娱乐游戏段弹性大（5-10 章） | 主类型+次要类型（≤30%） |
| 倒数第二卷 | 前半反派逼近，后半一败涂地 | 从次要类型回归主类型 |
| 末卷 | 从灵魂暗夜残留直推终局 | 主类型纯血回归 |

## 类型体系（10 种）

来自《救猫咪》+ 本引擎整合。

### 10 种类型速览

| # | 类型 | 情感承诺 | 节奏特点 |
|---|------|---------|---------|
| 1 | 傻瓜成功型 | 爽！ | 压抑-爆发循环 |
| 2 | 麻烦家伙型 | 太不容易了 | 持续压迫+小缓解 |
| 3 | 成长仪式型 | 终于变了 | 内在变化弧 |
| 4 | 金羊毛型 | 这路走得太值了 | 旅程+成长 |
| 5 | 屋里有怪物型 | 吓得我睡不着 | 悬疑+恐惧 |
| 6 | 傻瓜出局型 | 怎么会这样 | 反转+真相 |
| 7 | 伙伴之爱型 | 他俩太好了 | 情感+关系 |
| 8 | 制度化型 | 这代价太大了 | 群像+牺牲 |
| 9 | 犯罪动机型 | 真相太震撼了 | 推理+揭示 |
| 10 | 超级英雄型 | 普通人成了神 | 力量+责任 |

### 三层类型定位法

**第一层：全书主类型**（确定情感承诺）
- 例：选择"麻烦家伙型"作为主类型 → 整本书的爽感来自"看他如何扛过"

**第二层：故事线类型矩阵**
- 例：主线麻烦家伙型 + 感情线伙伴之爱型 + 副线屋里有怪物型

**第三层：卷级类型侧重**
- 例：卷 1-3 麻烦家伙为主 + 卷 4-5 加入屋里有怪物（每卷 ≤30%）

### 慎混搭组合

| 组合 | 风险 | 解法 |
|------|------|------|
| 麻烦家伙型 + 成长仪式型 | 被动扛 vs 主动接受 | 成长仪式仅用于卷末"接受"段（≤30%） |
| 傻瓜成功型 + 制度化型 | 聚焦一人 vs 多人展示 | 制度化只做背景，不展开多角色 POV |
| 金羊毛型 + 屋里有怪物型 | 走出去 vs 锁死 | 只在路途中设计短期"封闭副本"（≤5 章） |

### 三驱动模式（来自联网取经）

| 驱动 | 核心动力 | 适用场景 | 特点 |
|------|---------|---------|------|
| 事件驱动 | 外部事件推 | 动作/冒险 | 节奏快、冲突密 |
| 角色驱动 | 内在需求推 | 情感/成长 | 深度刻画、情感细腻 |
| 设定驱动 | 世界观规则推 | 设定/系统 | 世界观复杂、规则明确 |

**混合策略示例**：
- 主驱动：事件驱动（玄幻/动作）
- 辅助驱动：角色驱动（感情线）
- 卷 1-3：事件为主
- 卷 4-5：角色为主
- 卷 6-7：事件为主

## 三态情感架构（升级项，来自联网取经）

每章/每卷/每部都有的 3 态：

| 情感态 | 效果学目标 | 结构学实现 | 典型技法 |
|--------|----------|-----------|----------|
| **压抑态** | 积蓄期待、制造张力 | 信息差、延迟满足、障碍堆叠 | 伏笔、悬念、困境升级 |
| **爆发态** | 情感释放、高潮体验 | 冲突对撞、反转揭示、节奏加速 | 爆点、预期违背、宣泄 |
| **余韵态** | 意犹未尽、回味空间 | 留白、余波、新悬念植入 | 开放结局、情感回响、伏笔暗埋 |

### 三态在章节中的分布

- 短章（3000 字）：压抑 60% + 爆发 30% + 余韵 10%
- 中章（5000 字）：压抑 50% + 爆发 35% + 余韵 15%
- 长章（7000 字）：压抑 40% + 爆发 40% + 余韵 20%

### 三态在卷中的分布

- 开卷：压抑为主（建立期待）
- 中段：压抑-爆发交替
- 末段：爆发为主 + 余韵
- 卷末余韵：新悬念植入（接下卷）

## 分卷规划（升级项）

### 6-8 卷原则

200 万字网文约 6-8 卷：
- 每卷 30-50 章
- 每卷 5-8 万字
- 每卷一个相对完整的故事弧
- 每卷末接续下卷

### 分卷规划模板

```yaml
volumes:
  - volume: 1
    title: 废材觉醒
    chapters: "1-50"
    word_count: 150000
    type_focus: "傻瓜成功型（纯血）"
    beats:
      - "开场画面：废材日常"
      - "催化剂：金手指觉醒"
      - "中点：第一次逆袭"
      - "一败涂地：反派碾压"
      - "高潮：绝地反击"
    climax: "主角反杀首个反派"
    end_hook: "更大势力浮出水面"
    emotion_arc: "压抑→爆发→余韵"

  - volume: 2
    title: 风云际会
    chapters: "51-100"
    type_focus: "傻瓜成功型 + 屋里有怪物型（30%）"
    ...
```

### 卷级类型侧重演进

基于主类型的演进路径：

| 卷位 | 主类型纯度 | 次要类型 |
|------|----------|----------|
| 卷 1 | 100% | 0 |
| 卷 2 | 80% | 20% |
| 卷 3 | 70% | 30% |
| ... | 70% | 30% |
| 卷 N | 100% | 0 |

**铁律**：每卷主导类型占该卷 60%+ 篇幅。

## 骨架检验

骨架完成后做 5 问：

1. **故事线清晰吗？** — 一句话能讲清楚吗？
2. **节拍完整吗？** — 15 个节拍都覆盖了吗？
3. **类型明确吗？** — 主类型 + 副类型有冲突吗？
4. **分卷合理吗？** — 每卷有独立弧 + 与整体衔接？
5. **节奏有起伏吗？** — 三态分布合理吗？

## 一句话总结

**架构 = DNA + 节拍 + 类型 + 分卷。** DNA 决定是什么，节拍决定怎么走，类型决定读者的情感承诺，分卷决定怎么卖钱。4 个齐备 = 骨架不散。
