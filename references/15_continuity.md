# 长篇连贯性与伏笔管理（Continuity & Foreshadowing）

> 30 万字后崩盘，三大杀手不是"写不好"，是"对不上"：
> **人物漂移**（OOC）、**设定矛盾**（前文说圆，后文说方）、**伏笔烂尾**（埋了不收 / 收了没埋）。
> 本文件给"跨章节一致性"的可执行机制，配合 `scripts/continuity_check.py` 自动巡检。

## 为什么长篇必崩

| 杀手 | 表现 | 读者感受 | 本书解法 |
|------|------|----------|----------|
| 人物漂移 | 主角第 5 章怕黑，第 50 章独自夜闯险地毫无反应 | "这还是那个人吗？" | 人物档案 + 伤口触发器 |
| 设定矛盾 | 第 10 章说"灵脉只生于北境"，第 80 章南境冒出灵脉 | "你前面说的什么？" | 设定登记表 + 自动巡检 |
| 伏笔烂尾 | 第 20 章"神秘玉佩"再无下文 | "挖坑不填" | 伏笔生命周期 + 回收预警 |

**核心原则**：一致性不是"写完再查"，是"写时记、写完对、定期扫"。

## 1. 四大追踪对象与记录规范

引擎在 `project_state.yaml` 和 `设定/` 下维护四类"真相源"（single source of truth）。

### 1.1 人物档案（character_profile）

每个核心角色一个 `设定/人物/XXX.yaml`，必须含：

```yaml
character:
  name: 林修远
  # 不可漂移项（漂移 = 硬伤）
  fixed:
    appearance: "中等身材，眉头旧疤"     # 外貌固定
    core_ability: "剑意·不屈"            # 核心能力固定
    scars: ["眉头疤", "左手三指旧伤"]    # 伤痕固定
    verbal_ticks: ["摸眉头疤"]            # 行为 tick 固定
  # 可变项（变化必须"被读者看见"）
  mutable:
    relationship: "与柳如烟：暧昧→误会"
    known_info: ["师门被灭真相"]          # 已知信息，只增不减
    heart_state: "从复仇到问心"           # 弧光进度
```

**漂移判定**：`fixed` 项跨章变化 = P0 红线；`known_info` 出现"前文从未铺垫的信息" = 因果断裂。

### 1.2 场景/世界观设定（world_facts）

```yaml
world_facts:
  geography:
    - id: WF-GEO-01
      fact: "灵脉只生于北境冰原"
      source_chapter: 10
      status: 锁定
  rules:
    - id: WF-RULE-01
      fact: "修为被废者不可重修"
      source_chapter: 1
      status: 锁定
  economy:
    - id: WF-ECO-01
      fact: "灵石等价 10 两白银"
      source_chapter: 15
```

**矛盾判定**：后文出现与 `status: 锁定` 事实冲突的设定 = P0 红线。

### 1.3 伏笔总表（foreshadowing_ledger）

```yaml
foreshadowing_ledger:
  - id: FS-001
    type: 物件          # 物件/人物/信息/设定/主题
    plant_text: "他从怀中摸出一枚古旧玉佩"
    plant_chapter: 10
    expected_recover: 80
    actual_recover: null   # null = 未回收
    status: 活跃
  - id: FS-002
    type: 信息
    plant_text: "那个人的眼神，他总觉得在哪见过"
    plant_chapter: 23
    expected_recover: 50
    actual_recover: 50
    recover_text: "原来那是他孪生兄长"
    status: 已回收
```

### 1.4 时间线（timeline）

```yaml
timeline:
  anchors:
    - id: TL-01
      event: "师父之死"
      chapter: 3
      relative: "故事开始 3 年前"
  sequence:
    - chapter: 10
      after: TL-01
      note: "距师父之死约 3 年"
```

## 2. 一致性校验清单（手动，每次体检用）

### 人物一致性

- [ ] 外貌/能力/伤痕是否和 `fixed` 一致？
- [ ] 已知信息是否只增不减、无穿帮？
- [ ] 关系变化是否"被读者看见"（不是突然跳变）？
- [ ] 行为是否从"心脏"长出来？

### 场景/设定一致性

- [ ] 地名/规则/货币是否前后一致？
- [ ] 新设定是否登记？还是偷偷加了没记录？
- [ ] `status: 锁定` 的事实是否被违反？

### 情节/因果一致性

- [ ] 因果链是否断？（角色突然知道没铺垫的事）
- [ ] 事件 consequences 是否在后续承接？
- [ ] 战力曲线是否连续？（不突然膨胀/塌缩）

### 伏笔一致性

- [ ] 埋了没收的：是否超 `expected_recover` 章节？（预警）
- [ ] 收了没埋的：回收逻辑是否自洽？
- [ ] 回收是否让读者"原来如此"？（不是"为收而收"）

## 3. 伏笔生命周期管理

### 3.1 三阶段

```
埋设（plant）→ 培育（nurture）→ 回收（recover）

埋设：给可识别标志（颜色/形状/声音/气味），看似不重要但细节清晰
培育：中间 1-2 次"回声"（同意象再现），保持读者记忆
回收：在前文逻辑内引爆，给"原来如此"的爽感
```

### 3.2 Chekhov 之枪 + 红鲱鱼

- **Chekhov 之枪**：第 1 章墙上的枪，第 100 章必须响。
- **红鲱鱼（假伏笔）**：故意埋但不回收，用来误导读者（需标记 `status: 误导`，避免巡检误报）。

### 3.3 伏笔密度监控

| 类型 | 密度 | 风险 |
|------|------|------|
| 章级 | 每章 1-2 个 | 过多 = 读者记不住 |
| 卷级 | 每卷 3-5 个 | 过少 = 平淡 |
| 全书级 | 5-10 个 | 超过 10 = 难收束 |

**巡检规则**：活跃伏笔 > 30 个未回收 → 预警"伏笔过载"。

## 4. 跨章连贯性工作流（每 5 万字 / 每卷末）

```
Step 1：自动巡检
  python scripts/continuity_check.py --project . --report
  → 输出 一致性报告.md（人物漂移/设定矛盾/伏笔烂尾/时间线冲突）

Step 2：对照校验清单（手动补自动查不出的）
  情感连续性、弧光进度、语气一致性

Step 3：修复（见 §5）
```

**和体检期的关系**：体检期（references/11_rescue.md）看"健康度 5 维"，本文件看"一致性 4 类"。两者互补：健康度掉可能是"写崩"，一致性破可能是"对不上"。

## 5. 发现矛盾后的修复策略

| 策略 | 适用 | 风险 | 做法 |
|------|------|------|------|
| 软修正 | 小矛盾 | 低 | 在后文悄悄圆回来，不读者察觉 |
| 转化为伏笔 | 大错误但能利用 | 中 | 把"错误"变成"有意为之的伏笔" |
| 硬修正（retcon） | 无法圆的硬伤 | 高 | 明确改写前文，需向读者说明 |

**优先级**：软修正 > 转化为伏笔 > 硬修正。

**示例**（发现"主角第 5 章怕黑，第 50 章夜闯无反应"）：
- 软修正：第 48 章加"他花了三年才敢再走夜路，今夜手心全是汗"
- 转化伏笔：揭示"他不怕黑，怕的是黑暗里会出现师父的鬼魂"
- 硬修正：改第 5 章，他本就不怕黑（需重读前文）

## 6. 与 continuity_check.py 集成

脚本扫描项目目录，自动维护并校验上述四类：

```
输入：项目目录（含 设定/ 规格/ 正文/）
输出：一致性报告.md + 更新 project_state.yaml 的 consistency 段
```

**字段约定**（脚本读这些约定，作者照此写）：

| 你写的 | 脚本怎么用 |
|--------|------------|
| `设定/人物/*.yaml` 的 `fixed` 段 | 跨章扫描正文，检测漂移 |
| `设定/世界观.md` 里的"锁定事实" | 检测后文矛盾 |
| 每章 spec 的 `foreshadowing` 段 | 自动汇总伏笔总表 |
| `大纲/分卷.md` 的时间锚点 | 检测时间线冲突 |

## 7. 一句话总结

**长篇不是"写长"，是"写对"。** 一致性是读者对一本书最隐秘的信任——他不一定说得出，但一旦崩了，书就弃了。人物档案 + 设定登记 + 伏笔总表 + 自动巡检 = 让你的 100 万字像一个人写的，而不是 100 个人拼的。
