# 多线编织法（Multi-line Weaving）

> 单线写薄、想写群像又写绕——这是中长篇史诗向（雪中悍刀行 / 诡秘之主式）作者最高频的崩点。
> 本文件不教"为什么要写多线"，只教"在本引擎里怎么把多线写精彩又不乱"。
> 触发：`config.multiline_mode: true`（默认开）。单线 / 短篇 / 盐选短文作者把 config 改 `false`，下文所有提示对你不出现。

## 它和引擎的关系（横切，不新增阶段）

多线不是第 12 阶段，是**横跨架构期 → 创作期 → 完结期**的一条暗线：

- 架构期定"树干 / 树枝"（锚点归一 + 漏斗开口）
- 创作期做"交替 / 信息差 / 情绪对冲"（执行）
- 完结期收"漏斗汇聚"（引爆）
- 体检期查"副线服务度"（诊断）

全部复用现有模块（钩子三层级、三态情感、伏笔生命周期、Fabula/Discourse、健康度），本文件只补"跨线编排"这层手艺。

## 一、锚点归一法 → 接「健康度·主线纯度」+「架构期副线设计」

**引擎已有抓手**：健康度 5 维的 `plot_purity`（核心目标推进度 vs 支线占比）；续命期"加副线必须服务主线"。

**升级落地**：架构期给每条副线填一张"服务卡"——

| 副线 | 它服务的主线目标 | 它指向的同一结局 | 独立成篇风险 |
|------|----------------|----------------|-------------|
| 反派内斗线 | 暴露暴君弱点 | 最终大决战前削弱敌方 | 高 / 中 / 低 |
| 小人物挣扎线 | 烘托战争代价 | 决战日平民抉择 | 高 / 中 / 低 |

**自检（架构期必过）**：任意一条副线答不出"它如何推进核心目标 / 指向最终大决战"→ 要么砍，要么重绑到树干。树枝再多，都得长在一个树干上。

## 二、悬念钩子交替法 → 接「钩子三层级 × 五类型」+「章节 spec」

**引擎已有抓手**：08 章节 spec 的 `hook_layout`（开头 / 内部 / 结尾三段钩）、钩子三层级（信息 / 情绪 / 认知）、五类型。

**升级落地**：单章钩子只管"这一章"，多线要管"跨线钩子链"。章节 spec 增可选段 `cross_line_hooks`（仅 `multiline_mode` 时填）：

```yaml
cross_line_hooks:
  - from_line: "主角线"            # A 线
    cut_at: "密室门推开瞬间"       # 高潮处掐断
    throw_to: "反派线"             # 转 B 线
    b_line_must: "B 线也带钩（不能写吃喝拉撒）"   # 前提：B 线有吸引力
  - chain: "A 挖坑 → B 填土 → C 埋伏笔 → D 引爆"
```

**铁律（来自方法论，落到引擎）**：
- A 线高潮掐断转 B 线时，**B 线必须也带钩**，否则读者弃书。
- 跨线编排目标：A 抛问题 / B 给线索 / C 揭背景，像拧麻花互相拉动。

## 三、信息差不对称 → 接「Discourse·info_hiding」+「角色 known_info」

**引擎已有抓手**：07 Discourse 层 `info_hiding / info_release`；15 角色档案 `known_info` 只增不减；三态情感 压抑态用"信息差"做技法。

**升级落地**：把"信息差"从被动技巧升为**主动设计矩阵**——

| 读者知 \ 角色知 | 角色 A 知 | 角色 A 不知 |
|----------------|----------|------------|
| **读者知** | 正常叙述 | **戏剧反讽**（鸿门宴已埋伏，看主角傻乐换衣） |
| **读者不知** | 悬念（A 暗棋） | 双误会对峙（A 以为 B 坏，B 以为 A 叛，读者知都护同一人） |

**设计动作（架构期 / 创作期）**：在 `多线时间轴.yaml` 的"已知信息"纵列标注每条线角色此刻知道什么，故意制造"读者 > 角色"或"双误解"节点——这就是单线模拟不出的张力。

## 四、节奏错位补偿 → 接「三态情感架构」

**引擎已有抓手**：三态情感（压抑 / 爆发 / 余韵）章 / 卷 / 部三级；续命期"情绪热力图"预防机制。

**升级落地**：三态情感原本是**单线**情绪曲线；多线把它变成**情绪对冲编排**——

| 主线此刻 | 切去副线 | 效果 |
|----------|---------|------|
| 压抑到极致（生死博弈） | 死党搞怪 / 宠物偷吃（几百字） | 情绪调节，让读者喘口气 |
| 刚爽完（装逼全场欢呼） | 阴影里敌人磨刀（暗线） | 乐极生悲，埋危机 |

**原则**：你控制的是读者**整体情绪曲线**像过山车——多线并进 = 情绪的对冲，不是剧情的并进。哪怕几百万字，全方位情绪刺激才不腻。

## 五、漏斗式汇聚 → 接「伏笔生命周期」+「完结期」

**引擎已有抓手**：15 伏笔生命周期（埋 → 培育 → 回收）；完结期"副线价值最大化""收束所有伏笔"。

**升级落地**：把"收网"显式成架构原则——

```
初期（开口大）：天南地北多线并行，线索繁杂
   ↓
中期（碰撞融合）：线索开始互相触碰、人物命运交织
   ↓
后期（缩视角）：主动缩减 POV，让角色因"精心安排的必然"向同一地点 / 事件汇聚
   ↓
收官（引爆）：铺垫几十万字的长线伏笔同时炸，所有火药聚同一个桶
```

**完结期检查（multiline_mode 时新增）**：
- [ ] 后期视角是否主动缩减？还是平行线拼盘？
- [ ] 长线伏笔是否在终局"同时引爆"而非零散收？
- [ ] 角色命运是否交织于同一事件？

## 六、实操：多线时间轴（Excel 管理法的结构化）

直接用 `templates/多线时间轴.yaml`：横轴 = 时间（章 / 日），纵轴 = 各线索，每格填**事件 + 角色状态 + 已知信息**。

它解决的真实 bug：
- A 线过了 3 天，B 线怎么才过 1 小时？（跨线时钟对齐）
- 配角在 A 线受重伤，B 线怎么活蹦乱跳？（跨线状态一致）

写大纲或每章后填一格，你就是上帝——"主角打怪时反派在赶路，两天后正好客栈相遇"的逻辑就有据可查。此表已由 `continuity_check.py` 自动校验（v2.3.0 起）：跑巡检时会读 `设定/多线时间轴.yaml`，自动抓 **时间轴倒流（日期模式）/ 后期断线 / 状态跳变（重伤→活蹦乱跳无过渡）/ 跨线同角色状态矛盾 / 收网未汇聚** 五类跨线 bug（命中即真实不一致）；并对**跨线角色**给一条"请人工核对各线 known 只增不减、无穿帮"的弱提示。注意：每格 `known` 是"该节点相关已知"（局部写法，不重列历史），故不做单线集合硬判——已知信息累积语义的正确校验在 `15_continuity` 的角色 `known_info` 因果链。

## 衔接速记

| 阶段 | 多线编织动作 |
|------|------------|
| 2 架构期 | 副线服务卡 + 初始化时间轴 + 漏斗开口设计 |
| 4 创作期 | 跨线钩子链 + 信息差矩阵 + 情绪对冲编排 |
| 6 体检期 | 副线服务度诊断（主纯度补充） |
| 9 完结期 | 漏斗汇聚收网 + 长线伏笔同爆 |

## 边界（不做什么）

- 单线 / 短篇作者：`multiline_mode: false`，本文件所有提示不出现。
- 本文件教**结构设计**，不代写正文（铁律①）。
- 不与现有钩子 / 三态情感 / 伏笔模块冲突，是它们的"跨线编排"补层。

## 一句话总结

**多线不是写三本短篇小说，是一棵树上长满树枝。** 锚点归一定树干、钩子交替拧麻花、信息差造反讽、情绪对冲控曲线、漏斗汇聚收全网——再加一张时间轴表，你就是上帝。
